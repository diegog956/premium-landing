# Original production-ready one-shot

## Purpose

Build one complete first-party landing while external directions are researched. This is an authored alternative, not a prototype, moodboard, template remix, or fallback for weak references.

## Independence

- Use the verified brief, brand kit, business evidence, customer language, approved assets, constraints, and conversion goal.
- Do not use external visual candidates discovered in the current run as input. Keep their screenshots, tokens, motifs, and analysis outside this track until its clean commit exists.
- Let `frontend-design` author the creative premise with freedom over composition, typography, hierarchy, imagery, density, rhythm, and interaction.
- Use `design-taste-frontend` v2 as an adversarial anti-slop challenger before implementation and against the rendered page. It may force reconsideration but cannot impose its own framework, font, component, or aesthetic defaults.
- Use `ui-ux-pro-max` only for targeted evidence. Do not average specialist outputs or create design by committee.

Record the chosen premise and rejected obvious defaults in `.premium-landing/brief.md`. The premise must be specific enough to constrain the entire page, not merely name an aesthetic.

## Copy gate

Produce the complete narrative through `copywriting` from verified facts and sourced customer language. Audit structure and conversion with `cro`. Run `humanizer` as an auditor before design lock.

When humanizer finds a credible cluster in agent-generated, unapproved copy, return the passage to `copywriting`, rewrite it without changing facts or manufacturing personality, and repeat factual, CRO, and humanizer checks. Do not expose known generic, inflated, symmetrical, slogan-stacked, or mechanically polished AI copy. Never change user-supplied or approved copy without permission.

## Silent internal proof

Implement the real header, hero, CTA path, and one representative section first. Capture desktop and mobile evidence, run the anti-slop gate and `ui-visual-validator`, and repair every blocking issue. Do not return control, expose this partial proof, or ask the operator to finish art direction.

Once it passes, continue immediately with the complete page. Distinctiveness must survive below the fold, on mobile, and in content-heavy sections. Motion follows the Emil workflow and cannot compensate for a generic static system.

## Production-ready local gate

Do not present the original until all applicable completion requirements in [build-and-qa.md](build-and-qa.md) pass, including:

- complete factual and humanized copy;
- coherent full-page visual system without known AI-slop patterns;
- real responsive desktop/mobile behavior;
- accessible navigation, controls, focus, contrast, semantics, and reduced motion;
- working primary conversion path and scoped integrations with synthetic test data;
- clean production build and no known critical runtime or console failures;
- performance-sensitive assets and motion;
- SEO/GEO/AEO foundations, canonical/indexing policy, sitemap/robots, structured data when justified, favicons, Open Graph, Twitter/X metadata, and a deliberate 1200x630 social image;
- final `impeccable`, `web-design-guidelines`, `ui-visual-validator`, `review-animations`, and `seo-audit` passes where applicable.

Missing credentials or external approvals may remain explicit deployment dependencies; do not call the landing production-ready when a required local implementation or test is still incomplete.

## Preservation and comparison

Commit the completed original on a clearly named Git branch or immutable commit before showing it. Return its loopback URL, desktop/mobile screenshots, commit SHA, short creative premise, and unresolved external dependencies alongside the external reference options.

If selected, record its system as the approved visual authority and continue only with requested refinements or deployment. If an external direction is selected, preserve the original commit, restore a clean baseline without deleting user work, and enter the normal fidelity-led design-proof workflow. Never blend them silently.
